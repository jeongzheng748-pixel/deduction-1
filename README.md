# deduction-1

빅토리아 시대 영국을 배경으로 한 브라우저 추리 게임. 첫 사건은 **「레이븐힐 저택의 마지막 잔」**이다.

1891년 11월, 아서 펨브로크 경이 안에서 잠긴 서재에서 독살된 채 발견된다. 브랜디 잔 밑에는 타자로 친 유서가 있다. 하틀리 경위가 오후 3시까지 기다려 주는 동안 현장을 살피고, 일곱 사람을 심문하고, 범인과 수법을 밝혀야 한다.

## 실행

빌드 과정이 없다. `index.html`을 브라우저로 열면 된다.

```bash
# 또는 간단한 로컬 서버로
python3 -m http.server 8000   # → http://localhost:8000
```

## 게임 방법

- **장소**: 장소를 고르고 물건을 조사한다. 조사 한 번에 10분.
- **인물**: 질문 한 번에 5분. 단서를 찾으면 새 질문이 생긴다(이름 옆 빨간 점).
- **수첩**: 모은 단서가 물증 · 문서 · 증언으로 정리된다.
- **고발**: 범인, 독의 위치, 독의 출처, 유서가 놓인 시각, 동기. 다섯 문항에 답한다.
- 오전 9시에 시작해 오후 3시에 조사가 끝난다. 전부 조사할 시간은 없다.
- 진행 상황은 브라우저에 자동 저장된다.

## 파일 구조

```
index.html          화면 틀
style.css           디자인 (라이트/다크 모드)
engine.js           게임 엔진. 사건 내용은 들어 있지 않다
cases/ravenhill.js  사건 데이터. 이야기 전부가 여기 있다
```

## 나만의 사건 만들기

`cases/ravenhill.js`를 복사해 `cases/my-case.js`를 만들고, `index.html`의 `<script src="cases/ravenhill.js">`를 새 파일로 바꾼다. 엔진은 건드릴 필요가 없다.

### 1. 단서 (`clues`)

```js
clues: {
  ring: { cat: "물증", title: "압지의 고리 자국", text: "수첩에 적힐 내용" },
}
```

`cat`은 `물증`, `문서`, `증언` 중 하나다.

### 2. 장소와 물건 (`locations`)

```js
{
  id: "study", name: "서재", tag: "사건 현장",
  desc: "장소 설명",
  items: [
    { id: "blotter", name: "책상 압지",
      text: ["조사했을 때 나오는 문단", "두 번째 문단"],
      clues: ["ring"] },                       // 조사하면 수첩에 기록
    { id: "drawer", name: "서랍",
      requires: ["watchkey"],                  // 이 단서가 있어야 열림
      lockedName: "잠긴 서랍",
      lockedText: "잠겨 있다. 열쇠가 필요하다.",
      text: ["..."], clues: ["ledger"] },
    { id: "typewriter", name: "타자기",
      text: ["..."],
      extra: [{ if: "note", text: "유서를 본 뒤라면 덧붙는 문장" }] }
  ]
}
```

### 3. 인물과 질문 (`people`)

```js
{
  id: "mary", name: "메리", role: "하녀, 17세", desc: "인물 설명",
  topics: [
    { id: "m1", q: "어젯밤 무엇을 보았나?", a: "대답", clues: ["mary_night"] },
    { id: "m5", q: "H. 브라더스를 아나?", requires: ["ledger"], a: "..." }
  ]
}
```

`requires`가 있는 질문은 그 단서를 찾기 전까지 보이지 않는다. 사건을 단계적으로 열어 가는 핵심 장치다.

### 4. 고발과 결말 (`accusation`)

- `questions`: 문항마다 `options`와 정답 `answer`. **첫 문항은 반드시 범인**이어야 결말이 제대로 갈린다.
- `solution`: 결말 화면에 보여 줄 해설 문단들.
- `endings`: `perfect`(전부 정답), `partial`(범인만 맞힘), `wrong`(범인 틀림), `suicide`(선택: 범인 문항에서 `suicide`를 골랐을 때).
- `ranks`: 맞힌 개수에 따른 칭호.

### 좋은 추리물을 위한 체크리스트

- **공정성**: 정답에 필요한 단서는 모두 플레이어가 찾을 수 있어야 한다. 해설에 처음 나오는 사실이 있으면 안 된다.
- **결정적 단서 하나**: 이 사건에선 압지의 고리 자국이다. 유서가 아서의 죽음 *뒤에* 놓였다는 것을 증명하고, 그 시간에 혼자 있던 사람을 가리킨다.
- **붉은 청어**: 수상하지만 범인이 아닌 사람마다 숨기는 비밀이 따로 있어야 한다(토머스의 £20, 엘리너의 동생, 크로스 박사의 빚).
- **모순**: 범인의 말이 다른 증언과 어긋나는 지점을 만든다(‘쥐약’ 대 ‘말벌약’, 월급 £3 대 송금 £8).
- **시간 압박**: `clock.deadline`을 조절해 난이도를 바꿀 수 있다. 모든 행동 시간의 합보다 짧게 잡으면 플레이어가 골라야 한다.
